### 点击无反应修复（CRITICAL）
**根因**：之前改进时引入了 `enhance: false` 不支持的 ES2020+ 语法，导致 JS 报错、页面事件全部失效。

修复的语法问题：
1. **`**` 指数运算符** → `Math.pow()` — insights.js（2 处，最关键，直接导致整个分析页崩溃）
2. **`??` 空值合并** → `!= null ? a : b` — utils/weather.js（9 处）
3. **`?.` 可选链** → `(obj || {}).prop` 或 `obj && obj.prop` — 跨 5 个文件（calendar.js 7处, day.js 12+处, home.js 2处, record.js 2处, weather.js 2处）

**教训**：enhance:false 环境下，禁止使用 `**`, `?.`, `??` 运算符。必须用 Math.pow()、逻辑与、三元表达式替代。

## 全局白屏根因定位与修复（CRITICAL）

用户报告：之前修复 `**`/`?.`/`??` 后，所有页面仍然白屏。

**根因**：代码中大量使用 **对象展开 `{...obj}`**（ES2018 语法），而 `enhance: false` 下基础 ES6 转译器无法处理 ES2018。当转译器遇到不认识的语法时，会导致文件编译失败，页面白屏。

此外，`Object.entries()` / `Object.values()` / `String.prototype.padStart()` 等 ES2017 API 也没有 polyfill，在旧设备上可能不可用。

### 修复内容

1. **启用 `enhance: true`**（project.config.json）
   - 从 `false` 改为 `true`，启用 Babel 增强编译器
   - 支持 ES6+ 全部语法转译（包括对象展开、可选链、空值合并等）

2. **添加 ES2017 API polyfill**（app.js 顶部）
   - `Object.entries()` — 遍历对象返回 [key, value] 数组
   - `Object.values()` — 遍历对象返回 value 数组
   - `String.prototype.padStart()` — 字符串前补零
   - 仅在原生方法不存在时添加，安全无副作用

3. **替换所有对象展开为 Object.assign()**（7 处）
   - `utils/weather.js:475` — mergeRealWeather 中 `{...baseData}` → `Object.assign({}, baseData, {...})`
   - `pages/home/home.js:280,404` — 天气缓存和待处理记录
   - `pages/day/day.js:124,190` — 记录增强和触发器信息
   - `pages/record/record.js:296` — 天气快照
   - `pages/profile/profile.js:518` — 图表数据点

4. **修复 moods.js 数组解构参数**
   - `.map(([emoji,name,score,color]) => ({...}))` → `.map(function(item) { return {emoji: item[0], ...} })`

5. **修复 weather.js for...of 循环**
   - `for (const w of pool)` → `for (var _i = 0; _i < pool.length; _i++) { var w = pool[_i]; ... }`

### 验证
- 全部 28 个 JS 文件通过 Node.js 语法检查
- 对象展开搜索结果为零（全部清除）

**教训**：`enhance: false` 下，ES2018+ 语法（对象展开 `{...obj}`）会导致编译失败。`es6: true` 只转译 ES6(ES2015) 语法，不处理 ES2017 API。最佳实践是启用 `enhance: true` + 添加必要的 polyfill。

## 第二轮白屏根因（CRITICAL — 真正的修复）

用户反馈：上一轮修复后（对象展开、polyfill、enhance:true），"我的"页面截图显示**仍然全白**。

### 排查突破：用 vm.runInContext 实际执行 Page()

之前用 `new Function(code)` 只能验证 JS 语法，无法发现 require 失败或 Page() 构造异常。建立 vm.runInContext 测试框架（mock wx 全局 API），结果发现 home 和 profile 报 `stats is not defined`。

### 真正的根因：`utils/smartReminder.js:66`

```js
var RHYTHM_SUGGESTIONS = [
  ...
  {
    condition: function(records, stats) {
      return stats.streak >= 3 && stats.streak < 7;
    },
    icon: '🔥',
    title: '保持势头，冲击7天连续',
    desc: '再坚持' + (7 - stats.streak) + '天就能解锁「周记录者」徽章',  // ← 致命！
    action: '继续记录'
  },
  ...
];
```

`desc` 的字符串拼接在**模块加载时**立即执行，但 `stats` 是 `condition` 函数的参数 —— 此时 `stats` 根本不存在 → 抛 `ReferenceError: stats is not defined` → `require('smartReminder')` 整个失败 → `home.js` 和 `profile.js`（两个引用该模块的 Page）构造失败 → **两个 Tab 页全空白**。

### 修复
1. desc 改为函数式：`desc: function(stats) { return '再坚持' + (7 - stats.streak) + '天就能解锁「周记录者」徽章'; }`
2. `getRhythmSuggestion` 调用时再求值：`var descText = (typeof suggestion.desc === 'function') ? suggestion.desc(stats) : suggestion.desc;`

### 验证
- 16/16 页面 VM 加载测试全部通过
- app.js + custom-tab-bar + 5 个 Tab 页全绿

### 方法论教训
- `new Function(code)` 只能测语法错误，测不到 require 链上的运行时崩溃
- 微信小程序的「白屏」症状几乎总是 JS 运行时错误或 WXML 解析错误，排查时必须实际执行 Page() 才能定位
- 已建立 `vm.runInContext` 回归测试模式，以后修改 utils/ 时必须跑一遍
- 模块顶层数组字面量里，**禁止引用任何函数参数**或运行时变量作为字符串拼接的一部分
